# Team Bodymechanik — Website

The Team Bodymechanik coaching site, built with Next.js 16 (App Router) and
Tailwind CSS v4. It's a single long page that sells the Desi Body Reset membership on Skool:
hero, stats, transformations, what's inside the membership, how it works,
testimonials, pricing (membership vs 1:1 coaching), about, FAQ, and the 1:1
coaching application / contact form.

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # production build
```

Deploying to sPanel is covered step by step in [DEPLOY.md](DEPLOY.md).

## Where things live

| Path | What's in it |
|---|---|
| [`src/lib/site.ts`](src/lib/site.ts) | **All copy** — Skool link and price, nav, stats, membership contents, plans, steps, testimonials, FAQ, social links |
| `src/components/sections/` | One file per page section |
| [`src/components/Header.tsx`](src/components/Header.tsx) | Sticky header, active-section highlight, scroll progress, mobile menu, back-to-top |
| [`src/app/api/contact/route.ts`](src/app/api/contact/route.ts) | The one endpoint every form posts to |
| [`src/lib/mail.ts`](src/lib/mail.ts) | Sends the notification email through Resend |
| `public/images/` | Web-sized WebP images |

To change wording, a testimonial or an FAQ answer, edit `site.ts` — you
shouldn't need to touch a component.

## Images

The source photos are 1–2 MB PNGs each (11 MB total). The site serves
pre-sized WebP copies instead (~0.5 MB total), generated by:

```bash
node scripts/optimize-images.mjs
```

It reads the originals from `team-bodymechanik-step6/assets/`, which is kept out
of git. To add or replace a transformation photo: drop the PNG in that folder,
re-run the script, and add an entry to `transformations` in `site.ts` if it's a
new one.

Next's on-the-fly image optimisation is switched off (`images.unoptimized` in
[`next.config.ts`](next.config.ts)). The images are already the right size, and
it keeps image resizing off a host that limits per-process memory.

## Forms

All three forms post to `POST /api/contact` with a `kind`:

| Form | `kind` | Required fields |
|---|---|---|
| Recipe signup | `recipes` | email |
| Enquiry — "a general question" | `contact` | name, email, message |
| Enquiry — "applying for coaching" | `apply` | name, email, goal (one of `site.goals`); message optional |

The application and contact forms are one form ([`Enquiry.tsx`](src/components/sections/Enquiry.tsx)). Its
first field is a `<select name="kind">`, so the choice is sent as `kind` and
the server validates accordingly; picking "applying for coaching" reveals the
Goal field. Both `#apply` and `#contact` links land on that section.

Each sends a notification email to `CONTACT_TO_EMAIL` with the visitor's address
as `Reply-To`, so replying goes straight back to them. Recipe signups are emailed
to you too — there's no mailing-list integration yet.

Configure in `.env.local` (see [`.env.example`](.env.example)):

```bash
RESEND_API_KEY=re_xxxxxxxxxxxx
CONTACT_TO_EMAIL=info@devmasterinc.com
CONTACT_FROM_EMAIL="Team Bodymechanik <noreply@teambodymechanik.com>"
```

Without them every form answers 503 and tells the visitor to use Instagram.

Protection: a honeypot field, per-field length caps, the goal checked against an
allowlist, CR/LF stripping so values can't inject email headers, HTML escaping in
the email body, and a best-effort 5-per-10-minutes-per-IP throttle (in-process,
so it resets on restart).

**Email is sent with `node:https`, not `fetch`.** Node's `fetch` parses HTTP with
a WebAssembly module, and on the production host the long-running server can't
allocate it — every `fetch` failed with `WebAssembly.instantiate(): Out of
memory`. Keep using `sendNotification` / the helper in `mail.ts` for any
outbound request you add to this app.

## Motion

- Hero: heading lines rise out of a mask one by one, metallic sweep on the gold
  words, the logo fades in and floats inside slowly rotating rings, rising embers
- Sections fade and slide in as they scroll into view — one
  `IntersectionObserver` for the whole page ([`RevealObserver.tsx`](src/components/RevealObserver.tsx))
- Gold ticker band, light streak across buttons, lifting cards with a drawn top
  rule, zoom on transformation photos
- Header condenses on scroll, underlines the section you're reading, and shows a
  progress bar

Everything is CSS-driven where possible. Under `prefers-reduced-motion` all of it
stops and content is shown immediately. Reveal styles only apply once a
pre-paint script confirms JavaScript is running, so the page is never blank
without JS.

## Layout notes

- Desktop nav appears at 1280px; below that it's the menu button
- Testimonials are a swipeable row on phones, a grid above 650px
- Don't name a CSS class after a Tailwind utility (`.collapse`, `.grid`…).
  Utilities beat the component layer, so the utility silently wins — that's why
  the conditional form field is `.field-reveal`
- `.btn` sets `min-width: fit-content`: it hides overflow for the hover streak,
  so a flex parent shrinking it would clip the label instead of wrapping
- `main` has `overflow-x: clip` — the slide-in reveals start elements offset
  sideways, and without it they widen the page on phones. Use `clip`, not
  `hidden`, or the sticky column in the application section stops sticking
